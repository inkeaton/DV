Methodology

This page summarizes how we turned 35 years (1990–2024) of IEEE VIS publication metadata into analysis-ready tables: first exploring the dataset, then cleaning it, then finding research themes, and finally enriching author and institution information for higher-quality insights.

Goal

Build a consistent dataset that supports trustworthy statistics and topic-level views of VIS research.

Key choices

EDA first (to understand noise), strict cleaning (for comparability), BERTopic (themes from text), OpenAlex + pycountry (standardized authors/institutions/countries).

Main challenges

Long time span, messy affiliations, name ambiguity, duplicate/old author IDs, and non-academic contributors.

Data sources

We combine a curated VIS publication dataset with an external scholarly graph to improve consistency for authors and institutions.

Primary dataset (VISPubData)

Public dataset of IEEE VIS publications (1990–2024), including titles, abstracts, keywords, paper types, awards, and metadata about authors/affiliations.

Source: https://www.vispubdata.org

Enrichment dataset (OpenAlex)

We query OpenAlex to retrieve standardized “work”, “author”, and “institution” records (when matches exist), which helps resolve inconsistent affiliation strings and adds structured institution info.

Country normalization (pycountry)

We use pycountry to normalize country names and ISO codes (e.g., “USA” vs “United States”), so geographic statistics are consistent across many formats and years.

Data cleaning and imputation

Because the dataset spans 35 years, the raw metadata contains missing fields and inconsistent formatting. We applied “safe” cleaning rules to keep the analysis comparable and reduce noise.

EDA-first decision (why it matters)

We started with Exploratory Data Analysis (EDA) to see the “real picture”: missing fields, changes over time, and which columns are reliable enough for downstream analysis. This helped us choose practical cleaning rules instead of guessing.

What we cleaned

  • Removed non-archival / miscellaneous entries (to keep research papers comparable).
  • Dropped unused or low-value columns (to simplify the dataset and avoid confusion).
  • Removed rows missing essential text/metadata needed for clustering and enrichment (e.g., empty abstracts or author fields).
  • Handled known problematic identifiers (e.g., DOI anomalies) to prevent incorrect matches.

Imputation / assumptions (lightweight)

  • We avoid “predicting” missing values; instead we use conservative defaults (e.g., missing counts treated as 0 for plots).
  • If a paper cannot be matched to OpenAlex, we keep it in the dataset (no forced deletion) and rely on local metadata.
  • Where identifiers are missing, we generate stable internal IDs so every paper remains traceable through the pipeline.

Data processing and analysis

The pipeline is designed to move from raw metadata to analysis-ready tables, with clear outputs for charts and interactive visualizations.

Pipeline (order and rationale)

  • 1
    EDA (first)

    We profiled the dataset (missingness, distributions, trends) to understand what is trustworthy and what is noisy.

  • 2
    Cleaning

    We standardize and filter data so later steps (topic modeling + enrichment) operate on consistent records.

  • 3
    Topic modeling (BERTopic)

    We cluster papers using text (title + abstract + keywords) to discover recurring research themes over time.

  • 4
    Enrichment (OpenAlex + pycountry)

    We improve author/institution/country consistency and produce clean tables for networks and geographic views.

Why BERTopic

  • Works well with scientific text by using modern language embeddings (captures meaning, not just keywords).
  • Produces interpretable clusters that can be labeled and grouped into broader “macro” categories.
  • Supports outlier handling (papers that don’t fit well into any topic are not forced into a wrong cluster).

Why OpenAlex enrichment

  • Helps standardize author and institution entities when the raw affiliation strings are inconsistent.
  • Provides structured institution metadata that is easier to map geographically.
  • Improves collaboration analysis by enabling cleaner author–author and institution–institution networks.

Limitations

The methodology reduces noise, but it cannot fully eliminate ambiguity in long-term publication metadata. Results should be interpreted with these constraints in mind.

Main challenges (what makes this hard)

  • Noisy dataset across 35 years: formats, naming conventions, and coverage change over time.
  • Same name, different people: two different authors can share the same first/last name.
  • Multiple IDs for one author: authors can appear with an “old” ID and a “new” ID in external systems.
  • Affiliations written many ways: the same institution can appear in many textual variants.
  • Same institution name, different places: some institutions share names across countries/regions.
  • Industry/private contributors: companies may have limited public metadata, making matching harder.

Methodological constraints

  • Matching uncertainty: OpenAlex matching may fail (missing DOI) or be imperfect (title similarity).
  • Topic modeling is not “ground truth”: clusters reflect patterns in language, not an official taxonomy.
  • Coverage differences: not every VIS paper will have complete enrichment data (authors/institutions/geo).
  • Geographic aggregation: even after normalization, some records may have missing or outdated country info.

How to interpret results

  • Use trends and comparisons as signals, not exact counts in every corner case.
  • When focusing on individuals/institutions, expect occasional merges/splits due to identity ambiguity.
  • For sensitive rankings (e.g., “top authors”), consider cross-checking against original records.
